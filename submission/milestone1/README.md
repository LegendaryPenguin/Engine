# Milestone 1 — submission evidence

Captured terminal output from real runs on my own machine, for grading.
Everything in this folder is generated by

```bash
./submission/milestone1/capture.sh
```

which runs each command and writes its stdout, stderr, wall clock and exit
code to the numbered file. Nothing here is typed in or edited afterwards —
if a run failed, the failure would be sitting in these files. Re-running the
script overwrites all of it.

Captured **2026-09-18**, macOS 25.6.0 (arm64), Python 3.12.14, yfinance
provider, 11 symbols (10 tickers + SPY benchmark), 2015-01-02 → 2026-09-18,
**32,395 bars**.

## Rubric mapping

### Data acquisition and reproducibility — 12 pts

- **Configurable universe from an approved source.** `01_config.txt`: the
  ticker list, window, benchmark and every threshold come from
  `config/default.yml`. There is no ticker or date literal anywhere in
  `marketengine/`. A different universe is a different YAML file.
- **Two providers behind one interface.** yfinance (default, no key) and
  Alpaca (`config/alpaca.yml`), both returning the identical schema, so
  `provider:` is the only line that changes. Alpaca's two-request
  raw/adjusted merge — the part most likely to be silently wrong, since
  Alpaca has no adjusted-close column — is unit-tested against stub
  responses in `tests/test_alpaca.py`, with two further tests gated on live
  credentials.
- **Reproducible by construction.** `10_run_manifest.json` carries the
  SHA-256 of the config file's *bytes*, every library version, the
  provider's adjustment policy, per-symbol coverage and the list of files
  written. Two sets of numbers can be proven to have come from the same
  inputs, which a list of tickers cannot do.
- **Incremental and idempotent.** `04_run_cold.txt` fetches 32,395 rows;
  `05_run_warm.txt`, run seconds later, fetches **0** and prints
  "everything requested is already on disk". Front-of-window coverage is
  decided from a record of what was *requested*
  (`data/raw/<provider>/_requests.json`), not from the earliest stored bar —
  those differ constantly (`window.start: 2015-01-01` is a holiday, and a
  symbol that listed mid-window has no earlier bars by definition), and
  comparing against the earliest bar re-downloaded eleven years on every
  single run until it was fixed.
- **Restatements propagate.** Each incremental request reaches five calendar
  days back into data already on disk and `write_raw` merges with
  `keep="last"`, because vendors restate recent bars. Without the overlap a
  late print stays wrong forever.

### Cleaning, alignment and storage — 10 pts

- **Three separate outputs**, per the data-engineering literature: the
  immutable raw vendor response (`data/raw/`, never modified), the clean
  analytical table (`data/curated/`), and a quality-event log
  (`quality_events.csv`). Cleaning is a separate stage precisely so all
  three can be re-derived.
- **Flag, do not delete.** `08_data_quality.txt` shows 16 flagged bars out
  of 32,395 and **0** quarantined. Each flagged row carries its flag name in
  the panel's `flags` column, is counted per symbol in `data_quality.csv`,
  and appears in the event log with the value that triggered it — e.g. NVDA
  +29.81% on 2016-11-11, SPY -3.17% on 2018-10-10. All kept. Deleting the
  hard days is how a backtest quietly starts outperforming.
- **The only removals are structural impossibilities**: a non-positive
  price, or a bar whose high is below its own low, open or close. There is
  no defensible guess at what the real number was. Those rows are
  quarantined into the event log with their values intact. The OHLC check
  carries a one-part-in-a-million relative tolerance, because vendors round
  to four decimals and a check that fires on rounding is a check nobody
  reads.
- **Prices are not forward-filled** (`max_ffill_days: 0`). A carried price
  is a fabricated 0% return followed by a fabricated real one, and filling
  past a security's last quote manufactures a zero-volatility series that
  every risk statistic then rewards. Missing sessions are flagged
  `MISSING_SESSION` and dropped, so a return spanning the hole is honestly a
  two-day return. The mechanism is retained and flagged
  (`FORWARD_FILLED`) for anyone who needs a gap-free matrix.
- **Alignment.** `07_query.txt`: all 11 symbols, 2,945 bars each, identical
  date range — the benchmark's own sessions define the calendar, and each
  symbol is reindexed only *within its own observed span*, which is what
  stops a fill from ever running past a last quote or before a listing.
- **Storage.** Parquet (one file per symbol raw, one curated panel) plus
  DuckDB **views** over it, so `07_query.txt` is real SQL against the real
  files with no load step and no copy to fall out of date.

### Analytics and benchmark calculations — 12 pts

- Every metric the brief asks for: daily returns, cumulative returns,
  rolling volatility at 21/63/252 days, the full correlation matrix, and
  rolling correlation to the benchmark. See `11_summary.md` and
  `data/outputs/baseline/`.
- Benchmark-relative: beta, annualised alpha, R², tracking error,
  information ratio, active return, and up/down capture — all from an OLS
  regression of excess returns, with pairwise windows for short histories.
- **Returns come from `adj_close`**, split *and* dividend adjusted, so they
  are total returns. Using `close` would read every dividend as a price drop
  and understate JNJ, XOM and TLT materially over eleven years.
- **Annualisation conventions stated and correct**: geometric for returns
  (CAGR), `sqrt(252)` for volatility, **arithmetic** for alpha (alpha is an
  average per-period abnormal return, not a compounded path), and the
  risk-free rate de-annualised geometrically rather than divided by 252.
- **Every analytics function is tested against a hand-computed closed
  form**, never against a snapshot of its own output (`02_tests.txt`). That
  discipline caught two real bugs: a Sharpe ratio of 7.2e16 on a constant
  series, because `if sd == 0` never fires when a constant series' sample
  standard deviation is 1e-19; and capture ratios that saturated
  (NVDA up-capture of 115,008, eight symbols at down-capture of exactly
  1.00) because the textbook ratio-of-compounded-totals breaks down over an
  eleven-year daily sample. Both are fixed with a regression test naming the
  bug it replaced.
- **VaR is the empirical 5th percentile**, not a Gaussian approximation,
  which understates the tail exactly when it matters.

### Code organisation and functionality — 10 pts

- Layered, with the boundary enforced rather than incidental: **only
  `ingest.py` touches the network.** `analytics.py` takes and returns pandas
  objects and reads nothing from disk, which is why every metric in it has a
  closed-form test.
- Every stage is separately runnable (`ingest`, `clean`, `analyze`,
  `report`, `bench`, `query`, `config`), so iterating on a chart costs no
  API calls.
- Config is parsed into frozen dataclasses once, at the edge, with total
  eager validation — a typo fails immediately with a named field instead of
  surfacing three modules later as a `KeyError` inside a rolling window.
- Provider errors and config errors print as one-line messages without a
  traceback: those mean the input or the vendor is wrong, and a traceback
  would imply the program is broken.
- **121 tests, 2 skipped, 1.25 seconds, zero network calls.** Providers are
  tested against stub responses; the 2 skips are live-API tests that run
  only when Alpaca credentials are present.
- Secrets never touch a config file: Alpaca credentials come from the
  environment or `.env` (gitignored), so every config is safe to commit.

### README and explanation — 6 pts

- Root [`README.md`](../../README.md): run instructions, every subcommand,
  the layer diagram, the canonical schema table, a reproducibility section,
  a speed-and-freshness section, the data sources with their caveats, an
  output inventory, and known limitations.
- **Eleven numbered "Assumptions that change the numbers"**, each naming the
  defensible alternative and what choosing it would do — total return vs
  price return, the calendar choice, the no-forward-fill decision, the
  flag-don't-delete rule, the two-armed extreme-return test, the
  annualisation conventions, the flat 2% risk-free rate, pairwise windows,
  geometric-mean capture ratios, and 252 as a convention. The same list is
  regenerated into the bottom of every report, because a number without them
  is not interpretable.
- Limitations are stated rather than hidden: daily bars only, US equities
  and ETFs, **survivorship bias** in a hand-picked universe of names that
  exist today, relative metrics need overlap, and the risk-free rate is flat
  across eleven years in which the real rate went from near zero to over 5%.
- [`ROADMAP.md`](../../ROADMAP.md) covers phases 2–9 with explicit exit
  criteria per phase, including the point-in-time data model, the two-price
  rule, the cost-sensitivity sweep, and the chronological train/test split.

## What this does not claim

- **Daily bars are not a live feed.** The floor on "delay from live pricing"
  for a daily close is the vendor's own end-of-day publication lag, minutes
  to hours after 16:00 New York. `bench` measures the staleness honestly
  instead of pretending it away; a separate low-latency quote path for
  execution is `ROADMAP.md` phase 4.
- **The newest bar may be provisional.** `06_latency_*.txt` warns when the
  last bar belongs to a session that has not closed. Its "close" is the last
  trade so far and its volume is partial.
- **The universe is survivors.** Every result on it is optimistic by an
  amount nothing in the output reveals. The fix is a point-in-time
  constituent list (`ROADMAP.md` phase 3), which is not free.
- **The 2% risk-free rate is a placeholder** affecting Sharpe, Sortino and
  alpha.
